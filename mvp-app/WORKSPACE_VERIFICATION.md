# 프로젝트·세션 생성과 기존 Codex 세션 추가

## 사용 방법

- 탐색기 **WORKSPACE 옆 ＋**: 프로젝트·대화룸 만들기.
- 룸 아래 **＋ 새 세션**: 이름 있는 세션 만들기. 선택 후 중앙에서 바로 대화할 수 있어.
- 룸 아래 **Codex 추가**: 현재 로그인으로 조회 가능한 로컬 Codex 세션을 검색·선택하고 추가해. 다음 페이지도 불러올 수 있어.

추가 방식은 두 가지야.

| 방식 | 동작 |
|---|---|
| 기록 가져오기 — 기본 | 사용자·Codex의 공개 텍스트를 복사하고 새 Arch 협업 세션에서 이어가. 원본 대화는 보존해. |
| 원본 이어쓰기 | 같은 Codex threadId를 연결해 원본 대화에 새 발언을 저장해. |

첨부파일·내부 추론·도구 원시 출력은 복사하지 않아. 원본 이어쓰기는 원본 앱과 동시에 사용하지 않아야 해. active로 확인되는 원본은 추가를 막지만 여러 Codex 프로세스 사이의 전역 잠금을 보장하는 기능은 아니야.

설치 버전의 `thread/resume`에는 Dynamic Tools를 새로 등록하는 필드가 없어. 원본 이어쓰기는 원래 있던 도구만 복원하고 Arch가 없으면 이를 안내해. 기록 가져오기는 새 `thread/start`에서 Arch 도구를 등록해. [공식 App Server 문서](https://learn.chatgpt.com/docs/app-server)

## 저장·실행과 호환성

- SQLite에 `rooms`, `chat_sessions`와 메시지의 `chat_session_id`를 추가했어. 버전 2 마이그레이션은 기존 기록을 보존해.
- 새 세션은 첫 메시지에서 지속 가능한 Codex thread를 만들고 ID를 저장해. 다시 선택하거나 재시작한 뒤 메시지를 보내면 같은 thread를 재개해.
- 예전 메모리 전용 세션은 열린 호출 복원을 가정하지 않고, 다음 사용자 입력 때 저장된 공개 기록으로 새 지속 세션을 시작해.
- 메시지·리뷰·대화 버전·모델에 전달하는 맥락을 세션별로 분리해. 다른 프로젝트의 입력은 섞이지 않아.
- 앱 전체 실행 큐는 하나야. 다른 세션 실행 중의 메시지는 그 세션의 큐에 저장되고, 화면 전환만으로 실행을 중단하지 않아.
- 가져온 기록은 추가 시점의 스냅샷이야. 외부 앱의 나중 발언을 실시간 동기화하지 않아. ESH가 모델에 전달하는 공유 기록은 최근 60개야.
- Strata/OpenCode 설정·인증을 변경하거나 별도로 로그인·로그아웃하지 않았어.

## 실제 GUI·CLI 검증

`evidence/workspace-20261018-041248/result.json`의 모든 검사가 통과했어. Mock AI 응답은 사용하지 않았어.

1. 실제 GUI로 프로젝트와 세션 A·B를 생성했어.
2. A에 기억시킨 `WORKSPACE_SOURCE_8417`이 B의 CLI 입력에 섞이지 않는지 대조했어. B에서도 이전 표식이 없다는 실제 답변을 받았어.
3. A로 돌아왔을 때 같은 threadId를 재개하고 이전 표식을 기억했어.
4. 실제 Codex 목록에서 A를 선택해 기록을 가져왔어. 사본은 새 threadId에서 실제 Arch 검토에 성공했고 도구 응답은 1회였어.
5. 같은 테스트 원본을 원본 이어쓰기 방식으로 추가하고 실제 원본 threadId에서 답변을 받았어. 테스트에서 만든 원본만 이어썼어.
6. 재시작 후 프로젝트·세션·메시지·선택 세션이 복원됐어.

- 원본 threadId: `01a14b47-f8f3-7052-b2cd-f5fa4948ba7d`.
- 사본 threadId: `01a14b48-30b6-7220-9070-78a1d2e4d15a`.

같은 폴더의 `workspace-gui.json`과 `audit.json`에 실제 화면과 CLI 증거가 있어. 첫 시도 `workspace-20261018-041153`은 잠긴 구버전 실행 파일로 시작돼 실패로 보존했고 성공으로 집계하지 않았어.

최종 빌드는 `evidence/panels-final-20261018-041522/`에서 저장된 실제 대화와 구버전 DB 복사본을 다시 열어 기존 패널·기록 호환성을 검사했어. 소스와 실행 파일 해시도 있어. Rust 테스트 7개, React·Tauri 빌드가 통과했고 확인 대상 설정·인증 및 technical-spike 원본 해시는 동일했어.

## 실행

기존 `esh-chat.exe`가 열려 있어 종료하거나 덮어쓰지 않고 **`src-tauri/target/debug/esh-chat-next.exe`**로 별도 빌드했어. 실제 데이터로 사용할 때는 기존 앱을 닫고 새 파일을 열어줘. 개발·빌드 명령도 새 대상을 사용해.

```powershell
npm test
npm run build:desktop
$env:PYTHONUTF8='1'
python scripts/verify_workspace.py
```

검증은 실제 CLI 로그인과 모델 사용량을 사용해. 격리된 DB와 검증 자체에서 만든 원본 세션만 사용해.

`workspace.rs`는 저장·격리·마이그레이션, `cli.rs`는 조회·읽기·재개, `engine.rs`는 연결 전환과 Blocking Delegation, `main.tsx`는 탐색기·생성·가져오기 창을 담당해.
