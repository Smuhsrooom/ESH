기존 Codex 세션 추가 화면 수정

- 검색창이 버튼을 밀어 ‘검색’ 글자가 줄바꿈되던 문제를 수정했어.
- 이전 실제 검증에서 생성한 세션 3개를 정확한 ID로 구분해 기본 목록에서 숨겼어. ‘검증 세션 표시’로 다시 확인할 수 있고 원본 기록은 삭제하지 않아.
- 이름이 없는 ESH 세션은 미리보기에 포함된 ESH 전달 문구와 JSON 맥락을 제거한 제목을 표시해. 원본 기록은 변경하지 않아.
- 긴 제목은 두 줄로 제한하고, 세션 선택 시 이름을 자동 입력해. 선택하지 않은 상태에서 추가 버튼이 비활성화되는 이유를 안내해.
- 새 검색 시 이전 선택과 페이지 커서를 초기화하고 오래된 조회 응답이 최신 결과를 덮지 못하게 했어.

검증: `evidence/import-ui-20261018-042203/result.json`, `import-ui-gui.json`.
실제 Codex CLI 목록을 Tauri WebView에서 조회했어. 모델 턴이나 새 테스트 세션은 만들지 않았어. Rust 회귀 테스트 7개 통과. technical-spike와 기존 설정·인증 파일 해시 동일.

추가 수정 (2026-10-18)

첫 수정은 ESH 검증 세션 3개만 숨겨서 기존 협업 테스트 CLI 기록이 계속 나타났어. 이제 `exec` 실행, 에이전트 하위 작업 경로·메타데이터, 확인한 Antigravity 협업 테스트 경로를 구분해 기본 목록에서 숨겨. ‘자동 실행·검증 세션 표시’로 모두 다시 볼 수 있어. 일반 CLI 대화나 영어 질문, 이름이 비슷한 다른 프로젝트는 이 이유만으로 숨기지 않아. 페이지에서 숨겨진 개수도 표시해.

검증: `node scripts/verify_external_threads.mjs`에서 실제 기록 27개 중 협업 테스트 경로 9개 분류와 일반 세션 보존, 제목 정리, 유사 경로 오탐 방지를 검사했어. `evidence/import-ui-20261018-042426/result.json`에는 실제 CLI + Tauri WebView에서 현재 페이지의 자동 실행·검증 기록 13개 숨김/다시 표시, 세션 선택 후 이름/버튼 활성화 검증 결과가 있어. 설정·인증·technical-spike 해시도 동일해.

수정본은 `src-tauri/target/debug/esh-chat-ui.exe`야. 이전 `esh-chat-fixed.exe`는 이번 변경이 들어 있지 않아. 기본 빌드 대상은 기존 `esh-chat-next`이며 기존 앱을 닫고 `npm run build:desktop`을 실행하면 같은 수정본으로 갱신돼.

실행 파일 이름 규칙 변경: 현재 수정본은 `src-tauri/target/debug/esh-chat-mvp1.exe`로 빌드했어. 다음 수정본부터 `esh-chat-mvp2.exe`처럼 번호를 올려. 위의 이전 실행 파일 이름은 당시 기록이야.
